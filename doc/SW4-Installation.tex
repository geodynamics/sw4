\section{Build requirements}
The \texttt{unified-backends} branch builds one execution backend per executable:
\texttt{OPENMP} for native CPU execution, \texttt{CUDA} for NVIDIA GPUs, or
\texttt{HIP} for AMD GPUs. Use separate build and installation directories for
each backend. There is no runtime backend switch or support for mixing CPU
and GPU solver ranks in one run.

All builds need C, C++, and Fortran compilers, compatible MPI libraries,
BLAS, and LAPACK. CPU execution also needs OpenMP. CMake 3.18 or newer is
required; the supplied presets and HIP backend require 3.21 or newer.
Use dependencies built with compatible compilers and the same MPI implementation.

\begin{center}
\begin{tabular}{|l|p{10cm}|}\hline
Feature & Additional requirements \\ \hline
Geographic projections & PROJ 6 or newer; configure with \texttt{USE\_PROJ=ON}. \\ \hline
HDF5 input/output & Parallel HDF5 C and high-level libraries;
\texttt{USE\_HDF5=ON}. Required for receiver HDF5, Sfile/GMG materials,
and HDF5 outputs. Serial HDF5 is rejected. \\ \hline
ZFP-compressed SSI & ZFP and H5Z-ZFP 1.1.0 or newer, plus HDF5;
\texttt{USE\_ZFP=ON}. Build ZFP with eight-bit bitstream words. \\ \hline
Random materials & Precision-matched MPI FFTW libraries;
\texttt{USE\_FFTW3=ON}. \\ \hline
CUDA or HIP solver & Matching GPU compiler and RAJA; Umpire is required with the default
\path{SW4_USE_UMPIRE=ON}.
Use the C++ standard required by those libraries
(\path{SW4_GPU_CXX_STANDARD=20} by default). \\ \hline
\end{tabular}
\end{center}

The optional I/O libraries and FFTW are disabled by default. Enable the
features required by the input deck. GPU builds use double precision;
\texttt{SW4\_PRECISION=single} is supported only for the native CPU solver.

\section{Build and install}
Run these commands from the repository root. Replace dependency paths and
compiler choices with those for your site. Set \texttt{CMAKE\_PREFIX\_PATH}
to the required dependency installation prefixes, separated by semicolons;
\texttt{HDF5\_ROOT} and \texttt{FFTW\_ROOT} can select those libraries explicitly.
Use an appropriate build concurrency for the host or allocation.

\subsection{Native CPU}
\begin{samepage}
\begin{verbatim}
cmake -S . -B build/cpu -DCMAKE_BUILD_TYPE=Release \
  -DSW4_BACKEND=OPENMP -DSW4_BUILD_MOPT=ON \
  -DUSE_PROJ=ON -DUSE_HDF5=ON -DUSE_ZFP=ON -DUSE_FFTW3=ON \
  -DCMAKE_INSTALL_RPATH_USE_LINK_PATH=ON \
  -DCMAKE_INSTALL_PREFIX="$PWD/install/cpu"
cmake --build build/cpu --parallel 4
cmake --install build/cpu
\end{verbatim}
\end{samepage}
The installed executables are \texttt{install/cpu/bin/sw4} and
\path{install/cpu/bin/sw4mopt}. Omit \texttt{SW4\_BUILD\_MOPT=ON} if
material inversion is not needed. This option is off by default.
The CPU backend does not require CUDA, HIP, RAJA, or Umpire.

\subsection{CUDA}
Configure after loading the CUDA compiler and MPI environment. RAJA and
Umpire must have CUDA enabled and support the target GPU architecture.
The architecture value below is for NVIDIA A100 GPUs:
\begin{samepage}
\begin{verbatim}
cmake -S . -B build/cuda -DCMAKE_BUILD_TYPE=Release \
  -DSW4_BACKEND=CUDA -DCMAKE_CUDA_ARCHITECTURES=80 \
  -DSW4_GPU_HOST_OPENMP=OFF -DSW4_BUILD_MOPT=OFF \
  -DUSE_PROJ=ON -DUSE_HDF5=ON -DUSE_ZFP=ON -DUSE_FFTW3=ON \
  -DCMAKE_INSTALL_RPATH_USE_LINK_PATH=ON \
  -DCMAKE_INSTALL_PREFIX="$PWD/install/cuda"
cmake --build build/cuda --parallel 4
cmake --install build/cuda
\end{verbatim}
\end{samepage}
The installed forward solver is \texttt{install/cuda/bin/sw4}.
CUDA host OpenMP is off by default. MPI uses staged host buffers by default
(\path{SW4_GPU_MPI_BUFFERS=STAGED}); experimental prefetch options are off.
A \texttt{sw4mopt} built with \texttt{SW4\_BUILD\_MOPT=ON}, including in a GPU
build tree, uses the native CPU inversion implementation.

For HIP, use a fresh directory, \texttt{SW4\_BACKEND=HIP}, a supported ROCm
compiler (set \texttt{CMAKE\_HIP\_COMPILER} to \texttt{amdclang++}, not \texttt{hipcc}),
matching RAJA/Umpire libraries, and the appropriate
\path{CMAKE_HIP_ARCHITECTURES}. The receiver and geometry checks reported
here have not validated HIP.

\subsection{Perlmutter environment}
The CPU and CUDA builds use separate prefixes under
\path{/global/cfs/cdirs/m3354/perl/sw4.unifybackend/install}:
\texttt{cpu/bin} and \texttt{cuda/bin}. Select the executable explicitly.
The build environment uses GNU 13.2, Cray MPICH, parallel HDF5 1.14.3.9,
and Cray FFTW; CUDA builds also load CUDA 13.2. The CUDA dependency stack
uses RAJA 2026.07.0 and Umpire 2026.07.1.

Retain the matching runtime libraries when moving or launching an executable.
Use the site's module environment and inspect \texttt{ldd} for missing
libraries. CPU builds must also be checked on CPU nodes; a build on a GPU
node alone does not establish CPU-node compatibility. Run simulations inside
an allocation, with the CPU or GPU account and node type appropriate to the
selected executable. Resource requests and queue limits follow current site
policy.

\section{Run and validate}
Use the MPI launcher for the MPI library used at build time. For example,
inside a suitable allocation:
\begin{samepage}
\begin{verbatim}
export OMP_NUM_THREADS=1
mpiexec -n 2 install/cpu/bin/sw4 test.in
\end{verbatim}
\end{samepage}
Replace the example input path with an existing deck and run from a directory
where its inputs and output paths resolve correctly. On Slurm systems use
\texttt{srun} with the allocation's process, thread, and GPU bindings.
Start GPU runs with one visible GPU per MPI rank. See
\texttt{SW4-UsersGuide.pdf} for input syntax and receiver metadata.

CTest is optional. Configure with \texttt{BUILD\_TESTING=ON}, select
\texttt{TESTING\_LEVEL} and \texttt{MPI\_NUM\_TEST\_PROCS}, then run
\begin{samepage}
\begin{verbatim}
ctest --test-dir build/cpu --output-on-failure -j1
\end{verbatim}
\end{samepage}
in an allocation
that supports the configured MPI launcher. The presets disable CTest by default.
The receiver regression entry points and their required executables are listed
in \path{receiver-template-input.md}; they are separate from CTest.

Receiver validation covers bounded metadata batches, malformed input,
flat/Gaussian receiver and source placement, and depth-gradient material
planes. The material-gradient Taylor check uses native CPU \texttt{sw4} and
\texttt{sw4mopt}, one Vp direction, and a small uniform model. These checks
do not establish GPU model-level adjoints, peak selection for representative
recordings, HIP correctness, or startup speedup at production scale.

\section{Legacy Make builds}
The Make workflow remains available with a site-specific
\texttt{configs/make.inc}. Its executables and object directories differ
from CMake's \texttt{build/<backend>/bin} layout. Keep Make and CMake outputs
separate and use the configuration matching the selected backend and libraries.
Do not reuse object files from another compiler or dependency stack.
